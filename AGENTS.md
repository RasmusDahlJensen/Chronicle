## Scope and collaboration

- Chronicle currently consists of the generated-world web page: seeded Platec landmass, climate, biomes, rivers and lakes, fertility and sparse resource sites, generated by the local host and inspected in the browser.
- On 1 October 2026, at the user's request, all civilization code was removed: tribes, settlements, countries, decision AI and planner research, the simulation server, saves/SQLite and civilization identity. The authored regional atlas study and the original terrain lab were removed at the same time. The user said the civilization design needs to be thought through more.
- `docs/VISION.md`, agreed with the user on 1 October 2026, defines the game and its civilizations and authorizes one run: slice G1, milestones M0, M1 and M2, a stop for user review, then M3, M3b, P (persistence) and M4–M9, each delivered as one or more slices with briefs. It is the source of truth for the game and its civilizations: where this file, the workflow, `docs/ARCHITECTURE.md`, `docs/BACKEND_RESEARCH.md`, earlier feature briefs, agent memory or Git history differ from it, VISION.md governs (geography stays with `docs/CHRONICLE_SPEC.md` except slice G1). Follow its agent rules together with this file; for its run they also govern process: verified slices continue to the next without user review except at its stop points, work is committed directly on `main` with milestone tags, and nothing is pushed. Civilization work outside that document is not authorized.
- The local branch `archive/civilization-v1` holds the removed civilization work as reference only. Do not merge, restore or port from it unless the user asks, and never check out, modify, rebase or delete it; inspect it only with `git log` or `git show` (VISION.md rules 7 and 10). The same removed work and its documents also exist on the remote branch `origin/feat/atlas-01` and in `main`'s history before `6feda3f`; treat them exactly like the archive. Their rules, contracts and acceptance criteria do not bind the new design.

## Implementation rules, once authorized

- Share world and simulation modules between the lab, the observer application, the headless study and automated scenarios. The simulation runs in the host worker; the browser receives its state only through `shared/` contracts and never imports `src/simulation` (VISION.md rule 4). Never build a second simulation for tests.
- Keep browser, renderer, shared core/contracts, HTTP, and compute dependencies separated. `npm run check:architecture` enforces current import rules through Biome; extend those rules and their negative scenarios when adding new module boundaries. Keep runtime verification for globals, worker entrypoints, and behavior beyond static imports.
- Keep world and any future simulation state independent of rendering and browser APIs. Preserve seeded, reproducible generation and stepping, with explicit accounting for anything a later simulation tracks. When changing released generation rules or tuning, increment `WORLD_GENERATOR_VERSION`; incompatible manifest/tile layouts or numeric code meanings also need a protocol version change.
- Do not substitute decorative statistics, cosmetic changes, or silent accounting exceptions for missing mechanics.
- Label test fixtures and development controls clearly; they are not product features.

## Verification and handoff

- Add or update regression tests for each changed behavior and its module/process connections. During implementation use focused checks; before every implementation handoff, run the complete `npm run check` and resolve failures. Record actual results; browser/build/headless results establish different things, and local checks do not imply CI ran.
- Protect agreed acceptance criteria: do not skip failures, weaken assertions, or replace expected results merely to get a pass. Explain and resolve any necessary expectation change explicitly.
- For failures, preserve the scenario and reproducible inputs before fixing behavior or balance. If repeated fixes yield no new evidence, return to diagnosis rather than stacking speculative patches. Broaden testing when evidence or milestone gates require it.
- Obtain independent agent review for consequential code changes and resolve material findings; record a gap if that review is unavailable. Follow the workflow's review package when handing the slice to the user.
- Before stopping or handing off, update the active brief (or, with no active slice, the workflow's current-stage record) with revision/uncommitted work, last verified result, unresolved issue, and exact next action. Preserve working checkpoints and unrelated user changes.
- Keep README accurate in the same change whenever prerequisites, installation, launch commands, ports, configuration, or verification steps change. Run affected documented commands before handing off. Keep everyday setup and launch simple: `npm ci`, then `npm start`.
- Use Node 24.20.0 and `npm ci` with the committed lockfile. `npm start` starts the watched local lab; `npm run check` includes architecture, vendored source/artifact integrity, types, headless/process tests, production build, and development/production Chromium scenarios. Install Chromium with `npx playwright install chromium`. GitHub CI uses the same complete gate; see README for setup and diagnostics.
